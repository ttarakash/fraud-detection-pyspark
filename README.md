# Выявление мошеннических транзакций (PySpark)

Классификация e-commerce транзакций на мошеннические и обычные с помощью Spark ML на 1,47 млн записей.

## Задача
Предсказать, является ли транзакция мошеннической (`Is Fraudulent`), по сумме, способу оплаты, категории товара, устройству, возрасту клиента и аккаунта, часу операции.

## Данные
- Датасет Kaggle «Fraudulent E-Commerce Transactions», файл `Fraudulent_E-Commerce_Transaction_Data.csv`: 1 472 952 строки, 16 колонок.
- Классы несбалансированы: **5% мошеннических** транзакций.
- Данные в репозиторий не включены. Чтобы запустить тетрадь, положите CSV в папку `data/`.

## Что сделано
1. **Загрузка и очистка в PySpark:** пропуски по колонкам, замена отрицательного возраста средним, заполнение числовых пропусков средними.
2. **Признаки:** из даты транзакции извлечены день недели, месяц и день месяца. Добавлен флаг `Address_Match`, совпадают ли адрес доставки и адрес плательщика.
3. **EDA:** распределения суммы, способа оплаты, категорий, возраста, баланс классов.
4. **Пайплайн Spark ML:** `StringIndexer` → `OneHotEncoder` → `VectorAssembler` → `StandardScaler`; разбиение train/test 80/20.
5. **Модели:** логистическая регрессия, Random Forest, градиентный бустинг (GBT).
6. **Оценка:** ROC-AUC, ROC-кривые, матрицы ошибок.

## Результаты (тестовая выборка, 294 389 транзакций)

| Модель | ROC-AUC | Precision (фрод) | Recall (фрод) |
|---|---|---|---|
| Логистическая регрессия | 0,765 | 0,88 | 0,11 |
| Random Forest | 0,795 | 0,87 | 0,05 |
| **GBT** | **0,801** | 0,69 | 0,10 |

## Выводы
- Лучший ROC-AUC у GBT: модель лучше остальных ранжирует транзакции по риску.
- При пороге 0,5 все модели находят только 5–11% мошеннических операций. Это типичный эффект дисбаланса классов: модель редко решается поставить класс «фрод».
- Следующие шаги: подобрать порог по precision/recall, взвесить классы, использовать PR-AUC как основную метрику и настроить гиперпараметры.
